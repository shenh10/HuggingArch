# Manually curated list of HF model IDs that have been verified against
# their built-in spec (backend/arch/models/*.yaml).
#
# Semantics:
#   - IDs listed here render as `built-in` in the UI (architecture is
#     covered AND the specific checkpoint has been reviewed).
#   - Any other ID whose config resolves via SpecLoader.match() still
#     works — it just renders as `cached` until you promote it here.
#
# Rules for adding an entry:
#   1. Run `python -m backend.inference.validate <model_id>` and confirm
#      `valid: true` with the three byte columns at diff 0
#      (model_storage_bytes / quantization_metadata_bytes /
#      checkpoint_storage_bytes — the last is anchored against the hub's
#      measured index total when the snapshot carries one). The
#      `total_params` block is a display-only diagnostic: for packed
#      checkpoints (FP4/MXFP4 stored two-per-byte) its "actual" side is a
#      container-element count, not a logical param count, so a gap there
#      is expected and needs NO note.
#   2. Sanity-check the per-layer breakdown / weight bytes in the dashboard.
#   3. Add the ID below under the relevant spec_name header.
#
# Format: one ID per line; lines starting with `#` and blank lines ignored.
# The `## <spec_name>` headers are purely organizational — the loader only
# cares about the IDs themselves.
